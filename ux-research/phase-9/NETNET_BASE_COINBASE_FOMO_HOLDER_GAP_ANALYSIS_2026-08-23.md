## Classification law

- **ALREADY IMPLEMENTED** — verify with regression coverage and leave intact.
- **PARTIALLY IMPLEMENTED** — extend the existing controller/query/adapter or research surface.
- **MISSING / CURRENT PHASE** — integrate at the named Phase 9 dependency after required approval.
- **MISSING / LATER** — retain as subordinate research/pre-work; do not promote into Phase 9 execution.
- **OPEN DECISION** — prepare recommendation, alternatives, failure modes, simulations and an exact approval request; do not guess.

Research, a type definition, an adapter boundary or a compiling preflight is not
a live financial implementation. Repository code is authoritative for present
implementation status; the newest explicit product decision is authoritative

## Immediate bounded implementation result

This reconciliation extends existing Phase 9 surfaces only:

- active gate/dependency/handoff text now reflects the GAS-only referral
  delivery law and records D06/D10 approval boundaries;
- reserve read truth explicitly excludes all protocol-owned liquidity and the
  Referral Reward Pool from monetary backing;
- a pure referral-claim preflight rejects USDC payouts, external venues and
  bailout funding, pauses unsafe internal conversions, and reconciles duplicate
  or interrupted claims without moving money;
- the Project GAS E2E command now includes the existing Phase 9 read-model suite;
- read-source configuration documentation now covers Reserve, activity and
  Crews adapters already present in the application.

It does **not** implement a Referral Reward Pool, liability ledger, internal
AMM/router, pricing source, fee allocation, token contract, GameBankroll, RNG,
AMO, production provider or deployment. Those remain at the dependency and
approval boundaries above.
