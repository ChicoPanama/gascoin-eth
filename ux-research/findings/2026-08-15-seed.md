# Seed Reference Findings — 2026-08-15

This file records evidence-backed findings before molecular browser capture begins. It is intentionally cross-category.

## Fomo — primary SocialFi benchmark

Official product updates show a persistent product thesis: social discovery should sit directly next to execution.

Observed/documented primitives to benchmark:
- global + following feeds;
- profiles and leaderboards;
- trader PnL/balance context attached to social content;
- trade thesis displayed in feed;
- same account/balance/positions across web and mobile;
- fast buy flows and cross-chain abstraction;
- notifications for followed traders' actions;
- social features reused across spot and perpetuals.

GAS translation:
- result cards become actionable social objects;
- `TRY CRUISE/BOOST/REDLINE` must preconfigure but never auto-submit a wager;
- profiles should carry provable game/trade history, not screenshot claims;
- following feed and global feed need distinct scan density;
- account/balance continuity must be identical across devices.

Sources:
- https://fomo.family/blog/february-2026-recap
- https://fomo.family/blog/announcing-fomo-web
- https://fomo.family/blog/perpetuals-now-on-fomo

## OKX Orbit — verified-performance social execution

Documented primitives:
- native social network inside the trading app;
- users may share PnL, win rate and historical performance;
- tagged assets in posts can be traded without leaving the social context;
- groups, livestreams and gated communities expand creator/community structure.

GAS translation:

- social content should carry context and an adjacent action;

## Polymarket — probability simplification

Documented primitives:
- prices are communicated as probabilities;
- shares settle to $1 for the correct outcome;
- positions can be sold before resolution;
- displayed probability derives from order-book state;
- market rules and resolution sources determine settlement, not the title alone.

GAS/Bracket translation:
- future Bracket event cards should make the decision variable immediately understandable;
- advanced order-book data belongs behind progressive disclosure;
- settlement/rules must remain accessible from the trading surface;
- market state must distinguish probability/mark, executable price and liquidity where relevant.

Sources:
- https://help.polymarket.com/en/articles/13364060-what-is-polymarket
- https://help.polymarket.com/en/articles/13364488-how-are-prices-calculated
- https://help.polymarket.com/en/articles/13364444-limit-orders

## Kalshi — quick execution + portfolio semantics

Documented primitives:
- Quick Orders are the simplest/faster immediate trading path;
- order panel accounts for average execution price when an order crosses multiple price levels;
- portfolio separates cash balance from live position value;
- portfolio exposes cost basis, current value and payout if the outcome resolves in the user's favor;
- order book can toggle bid/ask framing.

GAS/Bracket translation:
- simple/quick action should be default; advanced order control secondary;
- users need expected execution and price-impact clarity before confirmation;
- unified account UI must still distinguish spendable cash from marked position value when Bracket is added;
- potential payout should be explicit without forcing the user to compute it.

Sources:
- https://help.kalshi.com/en/articles/13823810-quick-orders
- https://help.kalshi.com/en/articles/13823844-portfolio
- https://help.kalshi.com/en/articles/13823828-the-orderbook

## Axiom / high-speed trading surfaces

Public Axiom materials emphasize keeping signals close to execution, wallet/social tracking, one-click strategies and execution speed.

GAS translation:
- live activity must never become decorative clutter; it should shorten discovery-to-action;
- expert modes may compress interaction while novice modes retain explanation;
- speed should be measured as perceived acknowledgement and ready-for-next-action, not only chain settlement time.

## Cross-product patterns already emerging

1. **Actionable social object** — social content contains a direct path into the referenced economic/game action.
2. **Verified context** — performance/history is stronger when derived from the platform, not screenshots.
3. **Unified identity and balance** — moving between surfaces should not feel like moving between protocols.
4. **Quick path + advanced disclosure** — default action is simple; order books, rules and complex controls remain accessible one layer deeper.
5. **Immediate acknowledgement** — every financial/game action must visually confirm receipt before backend finality.
6. **Explicit payout/value semantics** — do not make users mentally convert probabilities, multipliers or marked value.
7. **Persistent network presence** — feeds/activity/network state make the system feel live, but must remain truthful.
